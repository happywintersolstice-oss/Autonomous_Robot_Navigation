This one-attempt study measures trace completeness on actual learning, with no navigation-performance claim. Its parent is Phase 5E commit `192ba8dca9957ac6d6b38965956b06f05b694548`. The new branch is `feature/phase5f-instrumented-learning-pilot-v1`. The supplied root brief and `configs/partial_phase5f_v1.yaml` are binding inputs.

## Scope sealed before learning

Run DQN, then PPO, once each, seed 23121, 500 genuine training actions per arm, at most 1,000 aggregate. Use only the eight existing open-grid Fixture A training cases stored in Phase 5B's training_cases array. Decode that array alone; do not construct or parse evaluation panels. The original environment validates these selected cases and selects each reset with its original uniform integer sampler. Initialize the environment case RNG and action space exactly as Phase 5B. Do not alter geometry, termination, rewards, sensors, features or algorithms.

Use original `partial_features_scaled.build_policy`, B1-relative-x4, the model section of `partial_feasibility_v1.yaml`, 409 raw values, 412 features, five actions. DQN uses replay 10000, learning_starts 100, batch 50, train_freq 4, gradient_steps 1, target sync 250, epsilon 1 to .1 with fraction .8. PPO uses n_steps 100, batch 50, n_epochs 5 and original library defaults. Both use gamma .99, learning rate .0003, layers [32,32], CPU, one environment, one Torch thread. One learn(total_timesteps=500, reset_num_timesteps=False) per model. The short learning horizon changes the schedule's time axis naturally; do not substitute a longer schedule horizon. Expect 100 DQN and 50 PPO real optimizer steps; counts are independently witnessed, not assigned from expectation.

No evaluation, checkpoint selection, extra seed, retry, additional algorithm, held-out layout, full Phase 5 or Phase 6. The final saved checkpoints are provenance artifacts only. No checkpoint loading or inference occurs during verification.
